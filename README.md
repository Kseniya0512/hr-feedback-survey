# Обратная связь по внедрению изменений · РТК ИТ

Готовое интерактивное приложение для обратной связи по квартальному пилоту фреймворка управления изменениями в HR. Два опроса: **22 нумерованных вопроса для команды внедрения** (0.1, 0.2 и 1–20; семь блоков 0–6) и **15 для участников изменений** (прежние пять блоков). Анкета команды обновлена для начала пилота; вопросы участников не изменены.

## Запуск

Для запуска на ноутбуке откройте **`HR-feedback.html`** в современном Chrome, Edge, Firefox или Safari: это готовое приложение одним файлом, со встроенными стилями и кодом. Его можно скопировать в отдельную папку.

Если файл открывается как текст или другой программой, нажмите правой кнопкой → «Открыть с помощью» → Google Chrome или Microsoft Edge. Если вы используете полный ZIP-архив, сначала выберите «Извлечь всё», затем откройте файл из распакованной папки.

Для разработки также сохранён исходный **`index.html`**: рядом с ним нужны `styles.css` и папка `js`. Открытие только этого файла без соседних ресурсов приводит к пустой странице. Интернет, установка пакетов, сборка и регистрация для локального режима не нужны. Сохраняйте папку проекта и используйте тот же браузер и адрес файла: доступность/область localStorage для `file://` зависит от браузера.

Альтернативный запуск с постоянным адресом, если браузер запрещает хранение при открытии файла:

```sh
cd hr-feedback-survey
python3 -m http.server 8080 --bind 127.0.0.1
```

Откройте локальный адрес сервера на порту 8080. Используйте один и тот же порт: другой origin имеет отдельное хранилище. Никакие данные этот статический сервер не собирает. Сборка не требуется.

## Что работает

- Стартовая страница с выбором роли и временем прохождения.
- Необязательные название инициативы, подразделение и, для команды внедрения, идентификатор инициативы перед началом.
- Семь блоков новой анкеты команды и пять прежней анкеты участников. Шкалы 1–5 с подписями, множественный выбор, необязательные комментарии до 5000 символов, валидация и возврат к ответам. Вопрос 4 команды — матрица из шести ролей: каждая строка 1–5 или «Не применимо / не знаком(а) с ролью».
- Вопрос 7 содержит только сложности, выбранные в вопросе 6, и скрывается при отсутствии проблем. Вопрос 9 появляется только при увеличении трудозатрат. Вопросы 14–16 видны после начала внедрения (все стадии кроме подготовки). Вопрос 17 — только при явной отметке «Новые правила уже запущены для сотрудников». При подготовке отметка скрыта; при возврате с этой стадии её нужно подтвердить заново.
- Отрицательные и ещё неприменявшиеся варианты исключают другие ответы в своём множественном вопросе. Вопрос 19 допускает максимум три варианта. Вопрос 3 раскрывает необязательное поле «Другое».
- Изменение стадии/затрат/набора сложностей очищает зависимые скрытые ответы в текущем черновике. Скрытые ответы из ранее импортированных записей не входят в аналитику, JSON- и CSV-экспорт.
- Отдельные автоматически сохраняемые черновики для каждого опроса и режима; «Начать заново» удаляет только текущий черновик после подтверждения.
- Экран благодарности появляется после успешного сохранения или подтверждения сервера.
- Четыре направления аналитики: понятность процесса и ролей; сложности и нагрузка; польза и восприятие; фактические результаты. Есть оценки по каждой роли, причины нагрузки, распределения, комментарии и отдельная статистика инициатив.
- Фильтры по инициативе, подразделению, стадии и роли. Стадия/роль относятся к новой анкете команды: при их выборе участники и архив не включаются в выборку.
- CSV для Excel и JSON, проверяемый импорт JSON без дубликатов.
- Адаптивность, управление клавиатурой, подписи шкал, поддержка reduced-motion.

Вопросы взяты из предоставленного задания. Отдельные методологические материалы фреймворка не предоставлялись. Приложение не вводит дополнительные обязательные правила работы по фреймворку. Все закрытые вопросы обязательны (за исключением скрытого условного); открытые комментарии добровольны. Отметка о фактическом запуске нужна только для управления видимостью вопроса 17, не является правилом фреймворка и не обязательна. Пять текстовых уровней готовности в сохранённой анкете участников соответствуют первоначальной пятибалльной шкале.

## Данные и ограничения

**По умолчанию включён локальный демонстрационный режим.** Ответы хранятся только в localStorage текущего браузера и origin. Ни автор проекта, ни другие сотрудники их автоматически не получают. Локальная аналитика открыта пользователю этого браузера и не является защищённой администраторской панелью.

Не запрашиваются имя, фамилия или email. **Анонимность не гарантируется:** инициатива, подразделение и свободный комментарий могут косвенно идентифицировать автора. Не вводите персональные данные в комментарии. Выгрузки содержат полные ответы — передавайте их в соответствии с корпоративными правилами.

Очистка данных браузера удалит ответы и черновики. Приватный режим, ограничения `file://` или переполнение хранилища могут помешать сохранению; интерфейс сообщает об ошибках. Регулярно делайте резервный **экспорт JSON**. Для объединения локальных ответов администратор может вручную импортировать JSON из других браузеров в один локальный браузер. CSV предназначен для анализа, его импорт не поддерживается.

JSON импорта: формат версии 1, максимум 5 МБ и 10 000 записей. Файл целиком проверяется до записи. Одинаковые ID с одинаковыми ответами пропускаются; одинаковые ID с разными данными отклоняют весь импорт. Порядок ключей объекта ответов не имеет значения. Ошибка импорта не удаляет текущие ответы.

CSV: UTF-8 с BOM, разделитель `;`, CRLF, кавычки и переносы экранируются; начало потенциальных формул защищено апострофом. Каждому вопросу отведён свой столбец с указанием аудитории. Экспортируется текущая отфильтрованная выборка; для полного экспорта сбросьте фильтры. Для восстановления нужен JSON.

Ключи localStorage:

- `hr-feedback.batch.v1.<UUID>` — пакеты новых завершённых ответов (одна атомарная запись для всего импорта);
- `hr-feedback.responses.v1` — совместимая исходная коллекция ответов, только чтение;
- `hr-feedback.draft.v2.<local|server>.implementer` — новая анкета команды;
- `hr-feedback.draft.v1.<local|server>.participant` — прежние черновики участников, без изменений;
- `hr-feedback.draft.v1.<local|server>.implementer` — старый черновик команды, сохраняется отдельно и доступен для скачивания перед новой анкетой;
- `hr-feedback.config.v1` — режим и адрес API, без токенов.

Не изменяйте содержимое хранилища вручную. Повреждённая коллекция ответов не перезаписывается автоматически. Повреждённый черновик блокирует продолжение до явного перезапуска; перед сбросом можно скачать его исходное содержимое. Новые ответы и импорт добавляются атомарно отдельными неизменяемыми пакетами в localStorage: запись из другой вкладки не заменяет общий список. Web Locks дополнительно координирует проверку дубликатов между вкладками. Не редактируйте один и тот же черновик одновременно в нескольких вкладках: при конфликте ID чтение будет остановлено без удаления исходных пакетов. В браузерах без Web Locks интерфейс показывает дополнительное предупреждение.

## Совместимость версий

Новые ответы команды имеют `questionnaireVersion: 2`. Для старых ответов команды отсутствие поля версии (или версия 1) означает прежнюю анкету. Конвертации старых `i1…i19` в новые вопросы нет: их смысл отличается. Старые записи остаются в локальном хранилище, импортируются/экспортируются и показываются в разделе архива со своими показателями. В новые средние они не входят. Черновики новой и прежней анкеты имеют разные ключи; старый черновик можно скачать в исходном виде, он не удаляется автоматически. Участники сохраняют прежнюю схему и ключ черновика.

Формат контейнера JSON остаётся `version: 1`; это версия файла, а не анкеты. Он может одновременно содержать старые/новые ответы команды и ответы участников. CSV добавляет версию анкеты, ID инициативы и раздельные столбцы для каждой роли матрицы, поля «Другое» и разных версий вопросов. JSON сохраняет вложенную матрицу. Скрытые ответы исключаются из экспортируемой копии; сохранённые исходные записи не изменяются.

## Как считаются показатели

Средние берутся только из числовых оценок соответствующей аудитории/версии и округляются при отображении до одного знака. Отсутствие числовых ответов отображается как **«Недостаточно данных»**. Число завершённых ответов может быть нулевым — это счётчик, а не оценка.

| Показатель | Аудитория | Вопросы | Шкала |
|---|---|---|---|
| Понятность процесса | Команда v2 | 1–2 | 1–5 |
| Понятность каждой роли | Команда v2 | отдельная строка матрицы 4 | 1–5 |
| Полезность фреймворка | Команда v2 | 10 | 1–5 |
| Польза относительно времени | Команда v2 | 11 | 1–5 |
| Понимание | Участники, без изменений | 1–3 | 1–5 |
| Коммуникации | Участники, без изменений | 4–5 | 1–5 |
| Поддержка | Участники, без изменений | 7–9 | 1–5 |
| Готовность | Участники, без изменений | 10 | 1–5 |
| Прежняя полезность | Архив команды v1 | 4–8 старой анкеты | 1–5 |
| Рекомендация/NPS | Только архив команды v1 | 19 старой анкеты | 0–10 |

«Не применимо», «Пока рано оценивать», «Не обращался(ась)» и другие специальные варианты не являются нулевыми оценками. Для множественного выбора доля — количество выбравших вариант / количество ответивших на применимый вопрос; сумма может превышать 100%. В причинах нагрузки знаменатель включает только ответивших на вопрос 9 после увеличения трудозатрат. Динамический вопрос 7 учитывает только респондентов с реальными выбранными сложностями.

Фактические результаты показываются отдельно **по ответам респондентов** и **по уникальным инициативам**. Для инициатив нужен общий `initiativeId` (до 100 символов), который респонденты вводят одинаково; приложение его не придумывает и не объединяет записи по одному названию. Ответы без ID остаются в статистике респондентов и не входят в инициативные доли. Для каждого ID берётся последний ответ в текущей отфильтрованной выборке по `createdAt` UTC; при равенстве — по ID ответа. Это выбранный способ агрегации сообщений респондентов, а не подтверждённый аудит инициатив.

Для каждой из четырёх событийных метрик отображаются числитель, собственный знаменатель и процент. Учитываются только видимые вопросы: непредвиденные сложности — 14; экстренные меры — 15; задержки — 16; повторные обращения/жалобы/несоблюдение — 17. «Пока рано оценивать» исключается; «Нет информации» исключается из повторных обращений; «Первоначального плана не было» исключается из доли задержек. При нулевом знаменателе показано «Недостаточно данных», а не 0%.

Для старой анкеты NPS = доля оценок 9–10 минус доля 0–6 (от −100 до 100); оценки 7–8 остаются в знаменателе. Новая анкета не содержит вопроса о рекомендации, поэтому архивный NPS не переносится на новый пилот.

## Централизованный сбор

Через кнопку **«Настройки»** выберите командный режим и укажите HTTPS-адрес API, например `https://survey.company.ru/api`. **Реализован клиентский адаптер и контракт подключения; готовый сервер и корпоративная авторизация не входят в проект.** Смена режима не переносит локальные ответы и не отправляет старые черновики.

Сервер должен реализовать `POST /responses`, `GET /session`, `GET /responses`. Для просмотра аналитики адаптер сначала проверяет серверную сессию с ролью `admin`. Сам сервер обязан независимо проверять права каждого запроса списка/экспорта: интерфейс не является границей безопасности. Никакого фиктивного JavaScript-пароля нет. Все запросы используют cookie-сессию (`credentials: include`); токены не сохраняются в коде/localStorage. Подробные схемы, идемпотентность, CORS, CSRF и требования к размещению: [docs/api.md](docs/api.md).

Для промышленного режима разместите статику и API на одном HTTPS-origin за корпоративным SSO. Открытие через `file://` для командного режима не рекомендуется: origin `null`, CORS и cookies обычно блокируются браузером. При ошибке сети или API ответ не объявляется отправленным, черновик остаётся доступен для повторной попытки.

## Проверка

Готовый `HR-feedback.html` создаётся из исходников командой `npm run build`; после изменения `index.html`, `styles.css` или `js/` пересоберите его. Unit-тест проверяет соответствие готового файла текущим исходникам. Браузерный тест отдельно запускает его без доступа к соседним CSS/JS, проверяет открытие анкеты и восстановление черновика.

Runtime-зависимостей нет. Для тестов данных нужен Node.js 22+ (использован 24).

```sh
npm test
```

Браузерные проверки используют бесплатный Playwright только как dev-зависимость:

```sh
npm ci
npx playwright install chromium
npm run test:browser
```

Системный Chromium можно выбрать через `CHROMIUM_PATH=/usr/bin/chromium`. Тест сам запускает и останавливает временный локальный HTTP-сервер. Для отдельной проверки открытия файла в браузере без корпоративного запрета `file://`: `FILE_MODE=1 npm run test:browser`. `SCREENSHOTS=1` сохраняет снимки в игнорируемую папку `test-results/`.

Покрыты оба полных маршрута, все пять стадий новой анкеты, отметка запуска, условия вопросов 7/9/14–17, матрица с пропусками/«Не применимо», восстановление частичной матрицы после перезагрузки, исключающие варианты, максимум три улучшения, переходы назад, аналитика, CSV и запрет серверной аналитики при 403. Неизменность схемы участников проверяется сравнением с исходной fixture версии 1. Unit-тесты дополнительно проверяют средние/NPS, отдельные роли, инициативные и респондентские знаменатели, скрытые импортированные ответы, совместимость версий, специальные значения, русский CSV, JSON, дубликаты, параллельную запись из двух вкладок и ошибки хранения/API. Дополнительные браузерные регрессии проверяют сохранность повреждённого черновика, блокировку полей во время отправки, повтор после ошибки, импорт с экранированием HTML и ширину 320px.

В облачной среде проверен HTTP-запуск. Проверка `file://` здесь ограничена политикой управляемого Chromium; код использует классические локальные скрипты и не требует fetch для локального режима. Работу с реальным корпоративным API необходимо проверить после его подключения.
