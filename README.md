# Обратная связь по внедрению изменений · РТК ИТ

Готовое интерактивное приложение для обратной связи по квартальному пилоту фреймворка управления изменениями в HR. Два опроса: **19 вопросов для команды внедрения** и **15 для участников изменений**, по пять блоков.

## Запуск

Скачайте проект целиком и откройте **`index.html`** в современном Chrome, Edge, Firefox или Safari. Интернет, установка пакетов, сборка и регистрация для локального режима не нужны. Сохраняйте папку проекта и используйте тот же браузер и адрес файла: доступность/область localStorage для `file://` зависит от браузера.

Альтернативный запуск с постоянным адресом, если браузер запрещает хранение при открытии файла:

```sh
cd hr-feedback-survey
python3 -m http.server 8080 --bind 127.0.0.1
```

Откройте локальный адрес сервера на порту 8080. Используйте один и тот же порт: другой origin имеет отдельное хранилище. Никакие данные этот статический сервер не собирает. Сборка не требуется.

## Что работает

- Стартовая страница с выбором роли и временем прохождения.
- Необязательные инициатива и подразделение перед началом.
- Пять блоков, шкалы 1–5 и 0–10, множественный выбор, комментарии до 5000 символов, валидация закрытых вопросов, возврат к ответам.
- «Проблем не было» исключает остальные проблемы и скрывает вопрос о помощи фреймворка. «Пока ничего» и «Сложностей нет» также исключают другие варианты в своём вопросе.
- Отдельные автоматически сохраняемые черновики для каждого опроса и режима; «Начать заново» удаляет только текущий черновик после подтверждения.
- Экран благодарности появляется после успешного сохранения или подтверждения сервера.
- Аналитика, фильтры по инициативе/подразделению, сравнение инициатив, все распределения и открытые комментарии.
- CSV для Excel и JSON, проверяемый импорт JSON без дубликатов.
- Адаптивность, управление клавиатурой, подписи шкал, поддержка reduced-motion.

Вопросы взяты из предоставленного задания. Отдельные методологические материалы фреймворка не предоставлялись. Приложение не вводит дополнительные обязательные правила работы по фреймворку. Все закрытые вопросы обязательны (за исключением скрытого условного); открытые комментарии добровольны. Пять текстовых уровней готовности сформулированы для указанной в задании пятибалльной шкалы.

## Данные и ограничения

**По умолчанию включён локальный демонстрационный режим.** Ответы хранятся только в localStorage текущего браузера и origin. Ни автор проекта, ни другие сотрудники их автоматически не получают. Локальная аналитика открыта пользователю этого браузера и не является защищённой администраторской панелью.

Не запрашиваются имя, фамилия или email. **Анонимность не гарантируется:** инициатива, подразделение и свободный комментарий могут косвенно идентифицировать автора. Не вводите персональные данные в комментарии. Выгрузки содержат полные ответы — передавайте их в соответствии с корпоративными правилами.

Очистка данных браузера удалит ответы и черновики. Приватный режим, ограничения `file://` или переполнение хранилища могут помешать сохранению; интерфейс сообщает об ошибках. Регулярно делайте резервный **экспорт JSON**. Для объединения локальных ответов администратор может вручную импортировать JSON из других браузеров в один локальный браузер. CSV предназначен для анализа, его импорт не поддерживается.

JSON импорта: формат версии 1, максимум 5 МБ и 10 000 записей. Файл целиком проверяется до записи. Одинаковые ID с одинаковыми ответами пропускаются; одинаковые ID с разными данными отклоняют весь импорт. Порядок ключей объекта ответов не имеет значения. Ошибка импорта не удаляет текущие ответы.

CSV: UTF-8 с BOM, разделитель `;`, CRLF, кавычки и переносы экранируются; начало потенциальных формул защищено апострофом. Каждому вопросу отведён свой столбец с указанием аудитории. Экспортируется текущая отфильтрованная выборка; для полного экспорта сбросьте фильтры. Для восстановления нужен JSON.

Ключи localStorage:

- `hr-feedback.batch.v1.<UUID>` — пакеты новых завершённых ответов (одна атомарная запись для всего импорта);
- `hr-feedback.responses.v1` — совместимая исходная коллекция ответов, только чтение;
- `hr-feedback.draft.v1.<local|server>.<implementer|participant>` — отдельные черновики;
- `hr-feedback.config.v1` — режим и адрес API, без токенов.

Не изменяйте содержимое хранилища вручную. Повреждённая коллекция ответов не перезаписывается автоматически. Повреждённый черновик блокирует продолжение до явного перезапуска; перед сбросом можно скачать его исходное содержимое. Новые ответы и импорт добавляются атомарно отдельными неизменяемыми пакетами в localStorage: запись из другой вкладки не заменяет общий список. Web Locks дополнительно координирует проверку дубликатов между вкладками. Не редактируйте один и тот же черновик одновременно в нескольких вкладках: при конфликте ID чтение будет остановлено без удаления исходных пакетов. В браузерах без Web Locks интерфейс показывает дополнительное предупреждение.

## Как считаются показатели

Среднее считается по всем числовым оценкам соответствующих вопросов в выбранной выборке, округляется только при отображении до одного знака. Прочерк означает отсутствие числовых ответов.

| Показатель | Аудитория | Вопросы | Шкала |
|---|---|---|---|
| Полезность фреймворка | Команда внедрения | 4–8 | 1–5 |
| Понимание | Участники | 1–3 | 1–5 |
| Коммуникации | Участники | 4–5 | 1–5 |
| Поддержка | Участники | 7–9 | 1–5 |
| Готовность | Участники | 10 | 1–5 |
| Рекомендация | Команда внедрения | 19 | 0–10 |

«Не обращался(ась)», «Не применимо», «Изменение ещё не запущено» не являются нулевыми оценками и в среднее не входят. Текстовый вопрос о понятности коммуникаций (6) выводится отдельно в распределениях. NPS = доля рекомендаций 9–10 минус доля 0–6, в процентных пунктах (от −100 до 100). Оценки 7–8 включены в знаменатель. Для множественного выбора процент — доля ответивших на вопрос, выбравших вариант; сумма может превышать 100%.

## Централизованный сбор

Через кнопку **«Настройки»** выберите командный режим и укажите HTTPS-адрес API, например `https://survey.company.ru/api`. **Реализован клиентский адаптер и контракт подключения; готовый сервер и корпоративная авторизация не входят в проект.** Смена режима не переносит локальные ответы и не отправляет старые черновики.

Сервер должен реализовать `POST /responses`, `GET /session`, `GET /responses`. Для просмотра аналитики адаптер сначала проверяет серверную сессию с ролью `admin`. Сам сервер обязан независимо проверять права каждого запроса списка/экспорта: интерфейс не является границей безопасности. Никакого фиктивного JavaScript-пароля нет. Все запросы используют cookie-сессию (`credentials: include`); токены не сохраняются в коде/localStorage. Подробные схемы, идемпотентность, CORS, CSRF и требования к размещению: [docs/api.md](docs/api.md).

Для промышленного режима разместите статику и API на одном HTTPS-origin за корпоративным SSO. Открытие через `file://` для командного режима не рекомендуется: origin `null`, CORS и cookies обычно блокируются браузером. При ошибке сети или API ответ не объявляется отправленным, черновик остаётся доступен для повторной попытки.

## Проверка

Runtime-зависимостей нет. Для тестов данных нужен Node.js 22+ (использован 24).

```sh
npm test
```

Браузерные проверки используют бесплатный Playwright только как dev-зависимость:

```sh
npm ci
npx playwright install chromium
npm run test:browser
```

Системный Chromium можно выбрать через `CHROMIUM_PATH=/usr/bin/chromium`. Тест сам запускает и останавливает временный локальный HTTP-сервер. Для отдельной проверки открытия файла в браузере без корпоративного запрета `file://`: `FILE_MODE=1 npm run test:browser`. `SCREENSHOTS=1` сохраняет снимки в игнорируемую папку `test-results/`.

Покрыты оба полных маршрута, обязательность, условный вопрос, исключающий выбор, переход назад, восстановление после перезагрузки, аналитика без смешивания аудиторий, выгрузка CSV, мобильная ширина и запрет серверной аналитики при 403. Unit-тесты дополнительно проверяют средние/NPS, специальные значения, русский CSV, JSON, дубликаты, параллельную запись из двух вкладок и ошибки хранения/API. Дополнительные браузерные регрессии проверяют сохранность повреждённого черновика, блокировку полей во время отправки, повтор после ошибки, импорт с экранированием HTML и ширину 320px.

В облачной среде проверен HTTP-запуск. Проверка `file://` здесь ограничена политикой управляемого Chromium; код использует классические локальные скрипты и не требует fetch для локального режима. Работу с реальным корпоративным API необходимо проверить после его подключения.
