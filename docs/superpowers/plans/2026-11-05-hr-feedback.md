# HR Feedback Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Готовое автономное приложение двух опросов и честной аналитики.
**Architecture:** Декларативная схема вопросов, чистые функции проверки/агрегации/обмена данными, адаптеры localStorage и API, отдельные представления интерфейса.
**Tech Stack:** HTML5, CSS3, vanilla JavaScript, Node built-in test runner; Playwright для браузерных проверок.
**Spec:** docs/superpowers/specs/2026-11-05-hr-feedback-design.md

## Global Constraints
- Полностью русский интерфейс, #8113FF, адаптивность, без регистрации в локальном режиме.
- Работает через file:// без сборки и внешних ресурсов.
- Никаких персональных полей, фиктивных паролей или обещаний централизованного локального хранения.
- Сохранить все 19 + 15 вопросов из задания.

## Review Focus
- Повреждённое хранилище / импорт: не затирать существующие данные; явно сообщать ошибку.
- Специальные значения и два опроса: не включать в числовые средние чужие вопросы.
- Повторная отправка / импорт: не дублировать записи.
- Сервер возвращает 401/403: не загружать аналитику, сохранить черновик при ошибке отправки.
- Длинные комментарии и русские строки: безопасный HTML, CSV с BOM и экранированием.

## Результат выполнения

Все четыре задачи завершены в исходной изолированной облачной рабочей копии; отдельный worktree не создавался. Независимое ревью выявило четыре случая потери данных; добавлены регрессии и исправлены: сохранение повреждённого черновика до явного сброса, отказ при конфликтующем ID, добавление неизменяемых пакетов вместо перезаписи общего списка, блокировка полей на время отправки. Дополнительно проверены 20 раундов параллельной записи двух вкладок и ширина 320px.

Техническое решение при проверке: одних Web Locks оказалось недостаточно из-за задержки синхронизации localStorage между процессами Chromium. Поэтому завершённые ответы записываются атомарными неизменяемыми пакетами под уникальными ключами; импорт целиком добавляется одним пакетом. Исходная коллекция поддерживается только для чтения. Одновременное редактирование одного черновика в нескольких вкладках не поддерживается и описано в README; независимые ответы не затираются.

Проверено: npm ci по lockfile; npm test — 16/16; npm run test:browser — полный маршрут двух опросов и 5/5 регрессионных сценариев. Серверные сценарии проверяются на контролируемых ответах API, не на реальном корпоративном сервере. file:// блокируется политикой управляемого браузера облачной среды; HTTP-запуск проверен. Исходники используют классические локальные скрипты без runtime-зависимостей. Изменения оставлены в рабочей копии для пользователя, без публикации и push.
