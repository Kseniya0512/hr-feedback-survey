# Обратная связь по внедрению изменений

Основа: предоставленное задание на 19 вопросов для команды внедрения и 15 для участников. Отдельные материалы методологии не приложены; приложение не добавляет правил фреймворка.

## Решение
Автономное приложение HTML/CSS/JavaScript без сборки, CDN и обязательных зависимостей. Классические скрипты работают при открытии index.html через file://. Поддерживаем компьютеры и телефоны, клавиатуру, reduced-motion. Белый фон, графитовый текст, акцент #8113FF; домашняя страница с двумя маршрутами, экран опроса с пятью блоками, аналитика и настройки.

Вместо SPA на фреймворке (потребовал бы сборки) или обязательного backend (нарушил бы автономный запуск) выбран небольшой статический клиент. Централизованный сбор подключается через отдельный API-адаптер, без фиктивного пароля или обещания анонимности.

## Поведение
Перед пятью блоками — необязательные инициатива и подразделение. Закрытые вопросы обязательны; открытые комментарии добровольны. Назад сохраняет ответы. Прогресс показывает блок и оставшиеся обязательные вопросы. «Проблем не было» скрывает вопрос о помощи с проблемами; исключающие варианты множественного выбора не совмещаются с другими. Каждому опросу и режиму соответствует свой черновик. Перезапуск требует подтверждения и удаляет только текущий черновик.

Локальные завершённые ответы живут только в браузере. CSV с BOM, разделителем ;, экранированием и защитой от формул; JSON сохраняет структурированные ответы, допускает проверяемый импорт с дедупликацией. Ошибки хранения видны пользователю. Нет автоматически созданных или вымышленных ответов.

Аналитика: числа ответов отдельно, полезность (вопросы 4–8 команды), понимание (1–3 участников), коммуникации (4–5), поддержка (7–9), готовность (10). В средние входят только числовые оценки, не специальные ответы. Рекомендации 0–10, распределение и NPS с явным определением. Все распределения, проблемы, комментарии, сравнение инициатив и фильтры по инициативе и подразделению.

Серверный адаптер: POST /responses; GET /session проверяет сессию администратора перед GET /responses. Доступ к данным и экспорту обязан контролировать backend. Cookies с credentials: include; HTTPS кроме localhost. Не сохраняем токены. Ошибки API сохраняют черновик, повторная отправка использует тот же idempotency key. Импорт локальный; переключение режимов не переносит ответы.

## Проверка
Node tests для схемы, проверки ответов, условного вопроса, агрегации, CSV и JSON. Браузерные тесты двух полных маршрутов, черновика, валидации, мобильной ширины, отказа API и server admin gate. README описывает автономный запуск, тесты и контракт API.
